# HPC 系統工程師學習與面試作品計畫

為鴻海 HPC 系統軟體工程師／架構師職缺設計。你曾任 SRE 與維運工程師、會 Linux、會一點程式，希望保留基礎；每週可投入 20 小時以上。現有 GCP VM 約 2 vCPU／4 GB RAM／100 GB disk，實際規格待確認。

## 從這裡開始

1. 看 [24 週完整課表](curriculum/ROADMAP.md)：每週主題及每天連結。
2. 看 [GCP 環境方案](ENVIRONMENT.md)：先用現有機器，多節點時再準備資源。
3. 從 [W01 D01](curriculum/week-01/day-01.md) 開始；每天的講義、實作與紀錄都放在同一份檔案。
4. [進度表](PROGRESS.md) 會依實際完成內容更新；專案目標在 [面試專案規格](project/README.md)。

## 學習方式

24 週是可調整的學習順序，約 480 小時，不是錄取保證。D1–D5 每天約 3 小時，D6 約 4 小時，D7 安排一個新主題；實際節奏依已有經驗與學習結果調整。已掌握的 Linux 基礎直接跳過，重點放在原理解釋、失敗案例與可重現紀錄。

每天已建立一份 Markdown，含導讀摘要、學習順序與實作主題。上課時會直接擴充當日檔案，將實際輸出與解釋追加為紀錄；不預先放空白表單、核取方塊或要求自行繪圖。

每天的結果與解釋保留在當日 Markdown。當天真的產生程式、設定、輸入檔、量測 CSV 或其他可重跑檔案時，才存到 [artifacts](artifacts/README.md) 的 `week-XX/day-YY/`，並由當日 Markdown 連結到該檔案。

你可以說：「開始 W01 D01」。當日 Markdown 是完整課程底稿，不需要在對話中重新朗讀。互動採逐步帶練：我先說明當下的小目標並只給一條指令；你執行後貼回結果；我解釋輸出、判斷是否正常、把真實結果整理進當日 Markdown，再提供下一條指令。觀念題給出標準答案後，會自動進到下一題；只有需要 VM 輸出或你的實際選擇時才停下來等候。需要組合多條指令的實驗，也會先說明原因，再逐步進行。

沒有實際輸出時只記錄待驗證，不代填成功；不會一次丟出整組指令要求自行消化。遇到卡點就在當前步驟排查，必要時補課，完成後才往下進行。

## 階段與能力門檻

| 週次 | 主線 | 通過條件 |
|---|---|---|
| 1–4 | Linux、Git、Shell 基礎重建 | 不看教學寫出可處理錯誤的維運腳本，說明權限、程序、服務與日誌 |
| 5–6 | Python 基礎與系統工具 | 健檢工具有參數、JSON、逾時、錯誤處理及實際測試 |
| 7–8 | 網路與共享儲存 | 依證據診斷連線，完成跨節點 SSH、名稱解析與 NFS |
| 9–11 | 架構、C、Ansible | 能編譯 C 程式，解讀資源，從乾淨 VM 自動部署基礎設定 |
| 12–14 | Slurm 與 MPI | 提交跨節點工作，證明 rank 分布與計算正確性，處理失敗工作 |
| 15–17 | 效能、Zabbix、故障處理 | 保存量測原始資料、告警與故障復原證據 |
| 18–19 | 平台比較與架構規劃 | 解釋 Slurm、K8s、OpenStack 分工，提出有假設與取捨的架構 |
| 20–22 | 專案整合、驗收、展示 | 新環境重建成功，十分鐘展示能呈現工作與故障復原 |
| 23–24 | 履歷、模擬面試、投遞 | 每項履歷主張有證據，能現場修改程式與排查問題 |

## 應徵定位

第一目標是「有 SRE／維運背景、具 HPC 入門實作的系統工程師」。架構師通常還需要規模、容量、硬體及長期營運的決策經驗。職缺的兩年以上經驗是否符合，要依你的實際年資及雇主認定；課程不能替代年資或學歷。

不必等 24 週結束才能投遞。第 14 週若已有可講清楚的跨節點作品，就可依職缺狀態嘗試投遞，誠實標示進行中項目；最後四週是集中整理。貼文的更新日期不能推定職缺會持續開放半年。
