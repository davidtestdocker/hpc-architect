# 模組 03：C/C++ 系統程式與 MPI 工作

[能力路線](ROADMAP.md)｜職缺條件：C、C++、Python；支撐能力：能開發、除錯並解釋 HPC 工作。

## 先教會的概念

編譯把原始碼變成目標檔，連結組成可執行檔；編譯成功不代表執行正確。C 的陣列邊界、指標與資源釋放，C++ 的型別、容器和資源生命週期，都影響系統程式可靠性。程序退出碼與標準錯誤輸出是呼叫者判斷失敗的介面。MPI 的 rank 是一個平行程序在通訊群中的編號，不是 CPU 核心；Slurm 的 ntasks 指程序數，cpus-per-task 指每個工作的 CPU 配額，不能互換。

MPI 範例只用來驗證排程、分布、資料切分與答案正確；它不是這份職缺要求深入數值演算法的證據。先做序列答案，再做平行版，處理工作量不能整除 rank 數的情況。多個 rank 可以都在同一台 VM；必須記錄各 rank 主機名才能證明跨節點。

例：10 筆資料分給 3 個 rank，可以分成 4、3、3 筆；三個部分結果合併後須等於序列版，不能漏掉最後一筆。

## 指令先講清楚，再操作

gcc／g++ 分別編譯 C／C++；警告選項幫助發現可疑程式，測試或 sanitizer 用來抓執行期錯誤，實際可用性依編譯器確認。mpicc／mpic++ 是 MPI 的編譯包裝器；mpirun 與 Slurm 的 srun 如何啟動 MPI，須依所裝版本及整合方式核對，不能隨意混用。sbatch 提交工作後，要看工作輸出與退出狀態，不只看提交回應。

## 實作主線與過關證據

在 project/workloads/ 完成一個小型 C++ 系統／資源觀察程式，要求明確參數、檔案或程序資訊讀取、錯誤處理及測試；另完成 C 或 C++ 的序列計算與 MPI 版本。測試零筆、單筆、不可整除、一般輸入與無效輸入；MPI 結果須與序列版一致。將可執行檔透過單節點 Slurm 提交；取得獨立 compute VM 後再驗證跨節點 rank 分布。不要把多 rank、跨 VM 與加速三者混成一件事。

過關證據含原始碼、編譯方法、測試輸入與預期答案、工作腳本、實際輸出和錯誤案例；能當場修改一個參數或修復一個失敗。至少能閱讀並修改 C 與 C++，其中一種要能獨立完成較深入程式。Go 因職缺寫「C/C++、Python 或 Go」而非全都必須，不另設主線。

開始帶練前，先在本文件追加本次確定的 VM 指令、目的與檔案影響；執行後記錄結果。尚未安裝編譯器或產生程式，不能寫成已驗證。
