# 模組 04：多節點網路與共享資料路徑

[能力路線](ROADMAP.md)｜職缺核心：網路系統設定與管理；支撐能力：叢集架構規劃。

## 先教會的概念

每個節點都需要可預期的位址、名稱、路由、時間和身分。位址可達不等於服務可用；DNS 解析成功也不等於防火牆允許連線。雲端防火牆與 VM 內部防火牆在不同層，排障要分開。管理、運算與儲存流量可共用教學網路，但在較大規模可能需要分開，原因是安全邊界、頻寬、延遲和故障影響。實體 VLAN、交換器、NIC bonding、RDMA 與 MTU 調校只在可取得相應環境時實測；GCP VM 不能假裝驗證了實體網路。

共享資料路徑有伺服器匯出、用戶端掛載、UID/GID 與逐層權限。NFS 能作教學案例，但不能代表所有 HPC 儲存；要知道它的單點故障、快取和效能限制。時間不一致或使用者身分不一致也可能表現為叢集服務或檔案存取失敗。

例：getent hosts 能解析 compute01，但 SSH 連不上時，下一步應查路由、服務監聽與兩層防火牆；不能再把它單純歸咎為 DNS。

## 指令先講清楚，再操作

ip addr 查介面位址，ip route 查路由；getent hosts 查系統實際名稱解析，ss 查本機監聽或連線；ssh 驗證身分和連線；findmnt 查掛載，namei -l 看路徑每層權限。這些命令各自只能觀察一層，不能單憑 ping 成功宣布整條工作路徑正常。雲端規則與客體防火牆的檢查方法依實際環境選定。

## 實作主線與過關證據

新增 VM 前先請學員確認規格、區域、費用及網路範圍；未同意不建付費資源。先做控制／運算節點間的位址、名稱、時間、SSH 和所需連接埠驗證，再建立共享工作資料路徑。以一般工作帳號驗證可讀寫，以不應存取的身分驗證拒絕。安排可復原的名稱解析、連線或 NFS 故障，從觀察到定位、修復與復測；事前寫明回復方式，不暴露叢集服務到公網。

project/docs/ 應有實際拓撲、位址與通訊矩陣、身分／權限設計；project/incidents/ 有真實故障紀錄。過關須有至少兩台獨立 VM 的互通與共享資料證據，並能指出故障發生在哪一層。只有一台 VM 時可以先學概念與單機部分，但跨節點能力標為未驗證。

開始帶練前，先在本文件追加本次確定的 VM 指令、目的及檔案／雲端資源影響；執行後記錄輸出與判讀。
