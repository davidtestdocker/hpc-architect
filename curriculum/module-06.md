# 模組 06：叢集維運、監控與故障復原

[能力路線](ROADMAP.md)｜支撐核心工作：獨立管理叢集；加分項：Zabbix 經驗。

## 先教會的概念

「主機可連線」「服務在執行」「節點可接工作」「工作結果正確」是四層不同的健康狀態。事件排查從症狀、影響範圍和時間線開始，逐層縮小到網路、身分／權限、儲存、服務或工作程式；修好服務後還要重新提交工作驗證。監控要有資料來源、更新頻率、告警條件與恢復條件；單次畫面截圖不能證明持續監控。Zabbix 是職缺加分項，不是核心課程的硬性前置。

例：VM 可 SSH、slurmd 也 active，但節點是 DRAIN，仍不能接新工作；要從節點狀態與原因查起，恢復後再提交工作確認。

## 指令先講清楚，再操作

systemctl status 看服務狀態，journalctl -u 看服務日誌；sinfo／scontrol 看節點，squeue 看工作，健檢 CLI 看跨節點彙總。各命令可能只顯示局部資訊：服務 active 不證明工作可完成；異常工作也不一定是服務故障。若選 Zabbix，先教 host、item、trigger、event 分別代表監控對象、資料、判斷條件與事件，再建告警。

## 實作主線與過關證據

擴充 project/healthcheck/ 工具：查各節點和 Slurm 狀態，保留逾時及部分失敗，不把未知當正常。先用原生狀態和日誌完成診斷，核心故障演練至少包含名稱／連線、共享路徑／權限、slurmd 或節點不可用。每次確認無重要工作、先記預期影響與復原方式，再注入可控故障；記錄症狀、證據、根因假設、修復和工作復測。若時間與資源允許，將其中一個真實故障接入 Zabbix，驗證資料持續更新、告警觸發和恢復。

project/incidents/ 留三份可檢查的事件紀錄，project/healthcheck/ 留測試；若做 Zabbix，加上 project/monitoring/ 的非敏感設定。核心過關是能獨立定位與恢復並以工作證明；沒有實做 Zabbix 就清楚標示加分項未完成，不影響核心過關。

開始帶練前，先在本文件追加本次確定的 VM 指令、目的、影響與回復方法；執行後記錄實際結果。
