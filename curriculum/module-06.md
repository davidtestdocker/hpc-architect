# 模組 6：監控與故障復原

## 問題與必要知識

工作失敗或節點不可用時，能及時發現、縮小原因、恢復服務並提供可追溯證據。工具名稱本身不是成果；主機存活也不等於能執行工作。

## 實作與完成標準

延伸 Python 健檢至節點與 Slurm 狀態，保留每節點結果、逾時與部分失敗。建立主機與服務層監控；若沿用目前專案規格，使用 Zabbix 驗證資料持續更新、故障觸發與恢復告警。演練名稱解析／網路、共享路徑或權限、slurmd／節點不可用。每次先確認沒有重要工作，留下症狀、觀察、判斷、修復與復測。

`project/healthcheck/` 有測試，`project/monitoring/` 有可重建設定與告警條件，`project/incidents/` 有至少三個真實、可恢復的事件。恢復後要提交工作驗證，不只看服務狀態。若環境不允許 Zabbix，先記替代方案和未覆蓋能力，不宣稱已完成原規格。

開始帶練前，先在本文件追加本次 VM 指令、目的、服務／檔案影響及復原方式；執行後補實際結果。
