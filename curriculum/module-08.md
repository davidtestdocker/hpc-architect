# 模組 08：面試作品與職缺能力證據

[能力路線](ROADMAP.md)｜目標：將前三項核心工作、程式能力與必要的加分項整理成可檢查的面試證據。

## 先教會的概念

作品不是截圖集合，而是他人依文件可以重建、測試與追問的系統。履歷中的「設計」「部署」「自動化」「優化」「維運」是不同主張，每個都要有相應檔案、命令結果或決策紀錄。教學規模的 GCP 叢集能證明方法與操作，不能冒稱企業硬體規模、實體高速網路或多年工作經驗。獨立作業與合作溝通可用清楚的操作手冊、設計決策、事件交接及英文技術說明展示，但不能假造團隊經歷。

例：若只提交過跨節點工作，可寫「建置並驗證跨節點工作」；沒有量測改善前，不能寫「優化叢集效能」。

## 先說明會用的檢查方式

Git 版本標籤／提交對應交付版本；README 指向安裝、執行、測試與復原方法。檢查命令依實際程式與部署文件逐項選，不用一條「總測試成功」取代排程、網路、程式、重建和故障驗證。展示時每個數字都要能回到原始資料；英文練習從自己的架構、故障和取捨出發，不背空泛自我介紹。

## 實作主線與過關證據

在新環境依文件重建核心作品，核對 CPU／GPU 節點、工作、程式答案、GPU 資源分配、部署重跑、共享資料與故障復原。整理十分鐘展示：需求與架構、部署、跨節點 CPU 工作、單 GPU 工作、故障處理、量測與限制。針對職缺原文逐項做「要求 → 實際證據 → 尚未驗證範圍」對照，演練現場修改 Python 或 C/C++ 程式、查 Slurm 工作和 GPU GRES、診斷網路／權限問題。用中文完整說明一次，再用英文精簡說明架構與一個故障；英文要求是可溝通，不強求華麗措辭。

過關需有可重建專案、測試與原始證據、部署／操作／復原手冊、架構取捨和可誠實寫入履歷的成果。學歷、兩年以上經歷是否符合是既有條件，課程不能替代。OpenStack／K8s／Zabbix 若未實做，只可描述概念，不能寫成經驗。

本模組若有新 VM 命令或專案檔案修改，也先在本文件記錄命令、目的與影響；完成後才寫實際結果。
