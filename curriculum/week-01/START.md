# 第一天詳細講義：從 SRE 的服務觀點理解 HPC

時間：3 小時。前置：可以登入現有 Linux VM。不需要安裝套件或新增雲端資源。

## 先理解工作模式（45 分鐘）

你過去可能維護長時間提供服務的程序；HPC 常見情境是使用者提交一份有結束時間的計算工作。兩者都要處理資源、權限、網路、儲存與故障，但使用者關心的結果和資源使用方式不同。

想像研究者要處理一百份資料：直接登入某台機器啟動一百個程式，容易發生資源爭搶。排程器接收工作與資源需求，再依配置與政策分配節點。程式是否真的平行，則取決於程式本身；有排程器不代表普通程式自動變快。

四個基本角色：

- 登入／提交入口：使用者準備程式、資料與工作腳本。
- 控制器／排程器：追蹤資源及工作，決定配置。
- 運算節點：實際執行程式。
- 儲存：保存输入、輸出與共用程式；不同系統可以採不同配置。

教學叢集可以讓登入入口、控制器、NFS 共用 head，但實體生產叢集不一定這樣做。Slurm 的控制與運算守護程序可先讀 [官方使用者指南](https://slurm.schedmd.com/quickstart.html) 的架構與基本命令部分。

## 觀察你的現有 VM（45 分鐘）

先在自己的 GCP VM 執行以下唯讀命令，一次一行，逐項解釋。不要把這裡的規格當成已驗證。

```bash
whoami
hostname
cat /etc/os-release
uname -r
lscpu
free -h
lsblk
df -h
ip -brief addr
ip route
```

記錄 OS 版本、核心版本、CPU 數量、可見記憶體、磁碟容量、檔案系統可用量。若命令不存在，先記錄缺少什麼，不必為完成第一天立刻安裝。

思考：`lsblk` 看區塊裝置，`df` 看已掛載檔案系統的空間，兩者回答不同問題；100 GB 磁碟不保證看到 100 GB 可用空間。Linux 的 `available` 記憶體也不等於 `free` 欄位。vCPU 描述客體可用的執行資源，不能據此宣稱擁有兩顆獨立實體 CPU。
